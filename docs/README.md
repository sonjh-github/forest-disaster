# 통합 문서 기준

이 디렉터리는 산림재난 통합시스템 구현에 직접 사용하는 가공 문서의 대표 위치다.
산불·산사태·용역 폴더에는 계약 및 연구의 공식 원본을 보존하고, 구현 과정에서
재작성한 API·요구사항 문서는 이 디렉터리에서만 관리한다.

## 포트폴리오에서 보여주는 역량

이 문서군은 공식 연구계획서·연차보고서·RFP를 그대로 요약한 자료가 아니다. 주관기관 관점에서 원문 요구를 구현 가능한 API·DB·컨소시엄 책임 경계로 변환하고, 참여기업·기관에 전달할 인터페이스와 시험 기준을 관리한 설계 증적이다. `확정(CONFIRMED)`, `추정(INFERRED)`, 통합 설계값(`DESIGNED`)을 분리하며 실제 코드와 연결되지 않은 요구는 `계획`, `골격`, `모사`로 표시한다.

## 문서 구조

- `api-docs/`: 통합 API, 장비·AI 연동 계약, 필드 근거와 OpenAPI
- `requirements/`: 공통·산불·산사태 요구사항, UI/UX 및 구현 현황
- `project-scope-and-api-boundaries.md`: 서비스 책임과 외부 연동 경계

## 관리 원칙

1. 공식 연구계획서·연차보고서·RFP 원본은 상위 도메인 폴더에서 변경하지 않는다.
2. API와 DB에 반영되는 해석본은 이 저장소에 한 번만 유지한다.
3. PDF 렌더, OCR 중간 산출물, 미리보기와 임시 압축본은 대표 문서에 반영한 후 제거한다.
4. 확정·추정·통합 설계 필드는 `api-docs/integrations/field-provenance.csv`에서 구분한다.
5. API 변경은 OpenAPI, 어댑터 계약, 테스트와 함께 갱신한다.

## 읽는 순서

1. [`project-scope-and-api-boundaries.md`](./project-scope-and-api-boundaries.md): 투비유니콘과 컨소시엄 참여기업·기관의 책임 경계
2. [`requirements`](./requirements): 공식 요구와 현재 구현 상태
3. [`api-docs`](./api-docs): 업무 API와 장비·AI 계약
4. [`test`](./test): 자동·DB·UI·실장비·비기능 검증 범위

문서상 목표 수치와 모사값은 실제 성능 달성 증거가 아니다. 실장비·기관망·AI 성적서는 별도 인수 증적으로 관리해야 한다.

## 인터페이스 관리 방식

통합팀은 OpenAPI와 장비·AI 상세 문서를 참여기업·기관에 전달할 기준본으로 사용한다. 회신된 endpoint, 인증, 필드, 오류코드와 장비 식별자는 근거등급과 버전을 갱신한 뒤 어댑터·모사 픽스처·테스트에 함께 반영한다. 구두 합의만으로 규격을 바꾸지 않고 변경 영향과 검증 결과가 남도록 관리한다.
