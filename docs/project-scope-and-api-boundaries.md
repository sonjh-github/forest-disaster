# 과제 범위 및 API 연계 경계

이 문서는 연구계획서와 연차보고서에 명시된 역할을 현재 구현에 대응시킨 납품 기준 문서다. `구현`은 현재 저장소에서 실행 가능한 기능, `모사`는 실장비 대신 시험 데이터를 만드는 기능, `계약`은 외부 업체가 구현해야 하는 API 경계를 뜻한다.

## 투비유니콘이 구현할 범위

- 산불·산사태 공통 사건, 장비, 인력, 위치, 상태, 경보, 작업, 권고, 상황보고 데이터 모델
- 장비·통신망·AI 결과를 받는 공통 JSON API와 외부 API 호출 어댑터
- 요청 UUID, 멱등성, 처리 상태, 오류, 상관관계 ID를 보존하는 연계 메시지 원장
- 지휘·상황 공유용 대시보드, 지도 시각화, 변경 강조, 운영기록
- 사용자 명령·권고 승인·경보 발령/확인의 감사기록
- 실증 KPI 측정값·원시 증빙 수집, 기준 대비 판정 및 표시
- 산불/산사태 특수 결과를 공통 사건 모델에 연결하는 도메인 어댑터
- 실제 연계 전 계약 검증을 위한 모사 서버와 GCS 변환 어댑터

## 투비유니콘 단독 개발 범위가 아닌 항목

| 과제 | 기능 | 계획서상 소관 | 투비유니콘이 제공하는 것 | 외부에서 반드시 제공할 것 |
| --- | --- | --- | --- | --- |

| 산불 | LPWA·RTK·RF 게이트웨이/망 제어 | 진인프라 | 상태·측위 수신 계약과 저장 | 게이트웨이 프로토콜, 측정값, 장비 인증정보 |
| 산불 | 5G/LEO 서비스 연속성, AI-RAN | ETRI | 상태·분석 결과 수신 계약 | 망 장비, 알고리즘, 품질 측정 API |

| 산불 | 기존 산불시스템 연계 | 산림청/운영기관 협의 | 변환 어댑터와 공통 API | 공식 연계 명세, 기관망 접근, 인증서·계정, 시험 창구 |
| 산사태 | 안정적 중계 통신망 및 현장 검증 | KT | 통신 상태·KPI 수신 및 표시 | 중계망, Supervisor 연계, 현장 측정 증빙 |
| 산사태 | 드론 탑재체·비행 소프트웨어 변경 | 천풍무인항공 | GCS/MAVLink 변환 어댑터와 결과 API | 실제 기체, 탑재체, 비행제어 변경, 안전 승인 |
| 산사태 | 요구조자 위치발신 장치 | 셀코 | Ref_AP/Rover 관측값 수신 계약 | Ref_AP/Rover 장비, RSSI·위상·진폭·RTK·RTT 원시값 |
| 공통 | 피해·확산·위험도 AI 모델 | 각 AI 개발 주체/공동 협의 | 입력·결과 계약, 모델 버전과 품질 메타데이터 저장 | 학습데이터, 검증된 모델, 추론 엔드포인트, 성능 성적서 |

외부 항목은 endpoint URL, 인증 방식, 타임아웃·재시도 정책, 오류코드, 샘플 페이로드, 장비 식별자 목록, 실증 KPI 산식이 확정되어야 실제 연동 완료로 볼 수 있다. 모사 성공을 실장비 연계 또는 성능 달성으로 표시하면 안 된다.

## 산사태 위치탐지의 현재 기준

- XY 위치는 최소 3개 `Ref_AP`, XYZ 위치는 최소 4개 `Ref_AP` 관측을 사용한다.
- `Rover_AP`는 격자 이동 Wi-Fi 스캔 관측을 제공한다.
- 수신 계약은 RSSI뿐 아니라 위상, 진폭, RTK, RTT를 보존한다.
- 현재 모사 결과는 `SIMULATED_NOT_FIELD_MEASURED`이며 현장 정확도 성적이 아니다.
- 실제 융합 알고리즘과 위치발신 장치는 외부 장비·검증 데이터 없이는 투비유니콘 단독으로 완료할 수 없다.

## 산불 대원 단말의 측위·통신 규약

모든 대원 단말은 다음 세 역할을 분리해 취급한다.

1. GNSS/RTK는 대원의 위치를 측정한다.
2. Wi-Fi/LTE 등 IP 통신은 차량 내 통신모듈 또는 현장망과 연결하는 주 통신이다.
3. LPWA는 주 통신 두절 시 위치·안전 상태를 최소 전송하는 비상 보조망이다.

따라서 `positioningMethod`를 통신 방식으로 사용하거나, LPWA를 평상시 주 통신으로 표시하면 안 된다. API는 `primaryLink`, `fallbackLink`, `activeLink`, `fallbackActivated`를 별도로 전달한다. LPWA로 전환된 경우 `activeLink=LPWA`, `fallbackActivated=true`가 동시에 성립해야 한다.

투비유니콘은 이 값을 수신·검증·저장·표시한다. GNSS/RTK 단말, Wi-Fi/LTE 모뎀, LPWA 무선장치, 차량 통신모듈의 펌웨어와 실제 망 전환 로직은 해당 장비·통신 업체의 개발 범위다.

## 장치 등록·배정·활성화 규약

현장 텔레메트리 수신만으로 장치를 자동등록하지 않는다. GCS와 드론도 동일한 사전등록 원칙을 적용한다.

1. 관리자가 `POST /assets`로 장치 코드, 일련번호, 소유기관과 기능을 등록한다.
2. 관리자가 `POST /assets/{assetId}/credentials`로 장치별 인증정보를 발급한다. 원문은 한 번만 반환하고 DB에는 해시만 저장한다.
3. 현장 투입 시 `POST /events/{eventId}/personnel-device-assignments`로 대원에게 단말을 배정한다.
4. 단말은 `POST /devices/activate`에서 장치 인증정보와 사건·대원 배정을 검증받는다.
5. 활성화 성공 시 15분 유효 장치 JWT를 발급한다. 텔레메트리 API는 토큰의 장치·사건·대원과 본문 식별자가 일치해야 한다.
6. 배정 해제 또는 인증정보 폐기 이후에는 재활성화를 허용하지 않는다.

장치 상태는 `REGISTERED → ACTIVE`를 정상 흐름으로 사용한다. 점검 또는 보안 사고 시 `SUSPENDED`, 분실 시 `LOST`, 영구 폐기 시 `RETIRED`로 변경하며 이 상태에서는 인증 발급·배정·활성화·데이터 수신을 거부한다. 상태 변경과 인증 발급·폐기는 모두 감사기록 대상이다.

GNSS·RTK·Wi-Fi·LTE·LPWA가 한 단말에 통합되어 있으면 `PERSONNEL_TERMINAL` 자산 한 대와 `capabilities` 목록으로 등록한다. 각 모듈이 별도 자산으로 정비·교체되는 경우에만 독립 자산과 상하위 구성관계로 관리한다.

투비유니콘은 자산 마스터, 인증 해시, 대원 배정, 활성화 검증과 감사기록을 구현한다. 기관 인증서 발급, 장치 보안영역에 인증정보를 주입하는 생산 공정, 장비 펌웨어와 실제 네트워크 전환 로직은 장비 업체·기관 PKI 소관이다.

## 운영 및 보안 기준

- 모든 쓰기 요청은 UUID `requestId`와 같은 `Idempotency-Key`를 사용한다.
- 서비스 계정 키는 브라우저·GCS·장비에 배포하지 않고 백엔드에만 둔다.
- 장비는 장비별 인증서 또는 제한된 토큰으로 백엔드 API에 접속한다.
- Supabase Data API의 신규 테이블 자동 노출에 의존하지 않고 권한을 명시한다.
- 운영 명령과 AI 권고는 승인 주체를 기록하며, 외부 RF/비행 제어는 소관 업체의 안전 절차를 거친다.

상세 요청·응답 형식은 [`forest-back-demo/docs/integrations.openapi.yaml`](../forest-back-demo/docs/integrations.openapi.yaml)을 기준으로 한다.
