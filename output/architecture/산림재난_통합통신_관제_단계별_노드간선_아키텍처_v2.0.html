노드-간선 원바이원 검토표 및 책임 경계

각 간선은 원문에 직접 명시된 기능, 계약 별첨의 납품 범위, 또는 투비유니콘 통합설계 중 하나로 구분했다. 제조사 원시 프로토콜이 없는 구간은 임의 확정하지 않았다. 제출용 · A3 가로 · 2/2

판정 기준

계획·연차 확인: 연구개발계획서 또는 연차보고서에 장비·망·데이터 흐름이 직접 명시됨.

계약 확인: 과업지시서 또는 물품공급·용역 명세서에 품명·기능·연계 대상이 직접 명시됨.

통합 설계: 표준 API 목표를 구현하기 위한 투비유니콘의 Northbound 계약. 장비사 수정안 수렴 후 확정.

배치 원칙

운영 목표는 KT Cloud의 Ingress/API와 PostgreSQL/PostGIS를 중심으로 구성하고, 대용량 영상은 객체저장소에 분리한다.

현재 Supabase 및 로컬 포트별 인스턴스는 개발·검증용이며 운영 아키텍처의 하위 대체환경이다.

제출 시 과장하면 안 되는 경계

  • 무전은 상황실-현장 음성 연계가 의무이나, 웹 대시보드의 음성 재생·녹음·PTT 원격조작은 원문에 직접 명시되지 않았다.
  • VR은 AI 통신음영 검증 결과·시나리오·로그의 관제 연계이며, HMD 실시간 영상 스트리밍이나 대시보드 내 VR 렌더링은 필수 범위가 아니다.
  • TVWS와 이음5G만으로 일반 인터넷/클라우드 연결이 완성되는 것은 아니다. Core·외부 IP 출구·LTE/위성/기관망·VPN 등 백홀이 필요하다.
  • 장비사가 제공하지 않은 Serial/전용 RF/비행·영상 프로토콜을 HTTP/JSON으로 단정하지 않는다. HTTP/JSON은 Gateway/GCS/NMS 이후 Northbound 우선안이다.
  • 재난문자로 일반 스마트폰 Wi-Fi를 임의 활성화하는 기능은 OS 정책상 제약이 있으며 정부·통신사·제조사 협력이 전제된다.
  • KT Cloud·PostgreSQL/PostGIS는 운영 실장 목표이고, 현재 Supabase·포트별 인스턴스는 개발·검증 환경으로 구분한다.

산불 원바이원 통신 절차

  1. 이동형 기준국/NTRIP 보정정보를 RTCM 기반 경량 데이터로 변환한다.
  2. LPWA Gateway가 보정정보를 대원 RTK 단말에 멀티캐스트하고, 단말은 보정 위치·상태를 회신한다.
  3. 무전 음성은 400MHz Gateway와 TVWS 오디오 연동을 통해 이동형 지휘소로 집선한다.
  4. TVWS·이음5G·LTE·LEO 가운데 가용 회선을 본딩/스위칭하여 외부 IP 백홀을 확보한다.
  5. Gateway/NMS Adapter가 UUID·사건·시각·위치·상태·품질을 통합 API 계약으로 정규화한다.
  6. Cloud DB·통신음영 AI·상황판이 저장·분석·표출하고, 경보와 운용결정은 현장으로 피드백한다.

산사태 원바이원 통신 절차

  1. 대원 단말은 드론 중계 LTE를 통해 위치·활동정보를 전송하고, GCS는 기체·임무·EOIR 상태를 수집한다.
  2. Ref_AP/Rover_AP는 스마트폰 Wi-Fi RSSI·위상·RTT를 수집하고 IR-UWB/GPR 탐지값을 좌표와 결합한다.
  3. KT Supervisor는 5G 품질·파라미터·틸팅·장애를 관리하고 CUSTOM GCS·DMS는 드론과 경보를 통합한다.
  4. 긴급통신복구차량/드론 중계가 LTE·5G·기관망 백홀로 Cloud Ingress에 현장 데이터를 전달한다.
  5. Northbound Adapter가 장비별 원시 규격을 보존하면서 공통 자산 UUID와 사건·시각·좌표를 부여한다.
  6. Cloud Container·위치융합 AI·3D 디지털트윈이 결과를 통합관제에 제공하고 현장 지휘로 환류한다.

공통 운영·DevOps 관측/피드백 절차

  1. 자산 등록 시 UUID와 제조번호·자산관리번호·장비유형을 매핑하고 연결 인스턴스를 식별한다.
  2. Gateway/GCS/NMS별 Adapter에서 인증·스키마·단위·좌표계·시각 동기화를 검증한다.
  3. Ingress에서 사건 단위 수집, 중복제거, 오류격리 후 PostgreSQL/PostGIS와 객체저장소에 분리 적재한다.
  4. 최근 수신시각·지연·손실·위치품질·보정상태를 관측하여 지도 간선의 정상/지연/두절 상태로 표현한다.
  5. API·DB 스키마와 장비 Adapter는 버전으로 배포하며 현장 규격 변경 시 개별 Adapter만 교체한다.
  6. 경보·운용결과·VR 검증로그를 감사기록으로 남기고 장애·성능 결과를 다음 배포와 망 운용에 반영한다.
